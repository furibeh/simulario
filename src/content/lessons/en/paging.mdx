<Stage stage="theory">

Every address a program uses is **virtual**. The operating system and the hardware translate it into a **physical** address in RAM.

Memory is cut into blocks of the same size: **pages** in virtual memory and **frames** in physical memory. Here they are 16 bytes; in real systems, 4 KiB.

A virtual address splits in two:

- **Page number** = address ÷ page size (integer division).
- **Offset** = the remainder.

With 16-byte pages, the offset is the 4 rightmost bits and the page number is the rest. For example, 70 = `100 0110`: page 4 (`100`), offset 6 (`0110`).

The **page table** says where each page is: in a frame, on disk (valid but not loaded) or invalid (not part of the program). The **physical address** is frame × page size + offset. The offset never changes.

The **TLB** is a tiny, fast cache inside the CPU with recent translations (page → frame). If the page is there (a hit), there is no need to read the page table. If not (a TLB miss), the table is read and the translation is stored; if the TLB is full, the one unused for the longest time is forgotten.

A **page fault** happens when the page is valid but on disk: the operating system loads it into a free frame, updates the table, and the access is repeated. It is slow, but normal. If the page is **invalid**, the system kills the process (segmentation fault).

Costs in this simulator: TLB 1, memory 100, page fault 10,000 time units.

</Stage>

<Stage stage="explain">

The right answer was: **TLB miss, hit, page fault, hit, TLB miss and invalid page**.

**A page fault is not an error.** The page table tells "on disk" apart from "invalid". Page 4 is on disk: the operating system loads it into the free frame and the access ends at physical address 22. Page 5 is not part of the program: that is an error, and Linux sends the `SIGSEGV` signal. Page faults are the normal way pages are loaded when needed (demand paging); a program can take thousands per second.

**What the TLB is for.** Without it, every access needs at least two memory reads: the page table and the data. Accesses 2 and 4 are on page 1, already in the TLB since access 1, so they skip the table. Real TLBs hold from tens to a few thousand entries and hit more than 99% of the time, because programs reuse nearby addresses (locality).

**Only the page number is translated.** The offset bits pass through unchanged: 20 = page 1, offset 4, and the physical address is 0 × 16 + 4 = 4. That is why the page size is a power of 2.

**Any page in any frame.** Page 0 is in frame 2 and page 1 in frame 0. Contiguous virtual memory does not need contiguous physical memory, which removes external fragmentation.

**Page faults dominate the cost.** The walkthrough costs 201 + 101 + 10,201 + 101 + 201 + 101 = 10,906 units, and the access with the page fault is 94% of that total. On a real machine the TLB answers in about 1 ns, DRAM in about 100 ns, and a page fault served from an SSD takes tens to hundreds of microseconds; from a hard disk, milliseconds.

**Evicting a page.** If no frame is free, the system moves a page out to disk (here, the one loaded first; the next lesson compares better choices). Its page-table entry goes back to "disk", and its TLB entry **must be removed**: otherwise the TLB would translate to a frame that now holds another page. The page is not lost: the next access to it is a page fault.

**Real page tables.** With 4 KiB pages and 48-bit addresses, a flat table would need 2³⁶ entries per process. x86-64 uses a 4-level tree (5 levels and 57-bit addresses on recent processors with LA57), so a TLB miss may walk 4 or 5 levels. Huge pages (2 MiB, 1 GiB) let a single TLB entry cover much more memory, and entries carry an address-space id (PCID) so the TLB does not have to be flushed on every context switch.

</Stage>

<Stage stage="deeper">

- **Multi-level tables by hand**, and inverted page tables.
- **Copy-on-write and memory-mapped files.** After `fork()`, parent and child share pages until one writes; `mmap` loads a file through page faults.
- **Minor and major faults.** A minor fault finds the page already in memory (for example, shared); a major one reads it from disk. `/usr/bin/time -v` and `perf stat -e page-faults` count them.
- **TLB shootdowns on multicore machines.** When a page leaves memory, every core that has it in its TLB must forget it.
