<Stage stage="theory">

A file system divides the disk into **blocks**: 4 bytes here, 4 KiB in real systems.

Every file has an **inode**, identified by its number. The inode stores the type (file, directory or symbolic link), the size, the **link count** and the pointers to its data blocks. The inode does **not** store the name.

A **directory** is a special file whose content is a list of entries `name → inode number`. Here there is a single directory, the root `/`: inode 0, stored in block 0.

Two **bitmaps** say which inodes and which blocks are in use (1) or free (0). New inodes and blocks take the lowest free number.

| Operation | Like | What it does |
| --- | --- | --- |
| `create name` | `open` with `O_CREAT \| O_EXCL` | New inode, empty file, new entry. Fails if the name exists. |
| `write name text` | writing the whole file | Frees the old blocks and takes ⌈length ÷ 4⌉ new ones. |
| `link old new` | `ln old new` | **Hard link**: another entry for the **same** inode; its count goes up. |
| `symlink target new` | `ln -s target new` | **Symbolic link**: a new inode whose content is the **name** `target`. |
| `unlink name` | `rm name` | Removes the entry; the count goes down. |
| `open name` / `close fd` | | Gives and returns a **file descriptor** (3, 4…). |
| `cat name` / `read fd` | | Reads through a name or through a descriptor. |
| `rename old new` | `mv old new` | Changes the entry's name. |

> Example: `create a` and then `write a "hey"`: inode 1, size 3, and block 1 holds `hey`.

</Stage>

<Stage stage="explain">

The right answers were: step 6 shows **"hola mundo"** and step 7 gives **an error**.

**The name is not the file.** The directory only maps names to numbers; everything else is in the inode. After step 3, `notas.txt` and `copia.txt` are two names for inode 1, and neither one is "the original". Removing `notas.txt` lowers inode 1's link count from 2 to 1 and nothing else changes. `ls -i` shows inode numbers and `stat` shows the link count.

**A hard link is not a copy.** No block was allocated: the data exists only once. A hard link cannot cross file systems (inode numbers belong to each file system), and most systems forbid hard links to directories so the tree has no cycles.

**A symbolic link stores a name.** `atajo` is a separate inode whose content is the text `notas.txt`. To read it, the system looks that name up in the directory, and at step 7 it is gone: a **dangling link**. Symbolic links can cross file systems and point to directories, but they keep nothing alive. ext4 stores short targets (under 60 bytes) inside the inode itself, with no blocks, just like this simulator.

**When data is freed.** Only when the link count reaches 0 **and** no process has the file open. A process can keep reading a file after its last name is removed; the space comes back when it closes it (the *Open file* script). `lsof +L1` lists such open, deleted files; on Linux they also show as `(deleted)` under `/proc/<pid>/fd`.

**Renaming does not move data.** `mv` within the same file system rewrites a directory entry; the inode number and every block stay where they were. That is why moving a 10 GB file is instant.

**Inodes run out too.** `df -i` shows how many are left. Many tiny files can exhaust the inodes while blocks are still free.

**Real systems.** ext4 uses 256-byte inodes and 4 KiB blocks, and describes data with **extents** (a starting block and a length) instead of one pointer per block. The classic Unix inode had 12 direct pointers plus single, double and triple indirect blocks.

</Stage>
