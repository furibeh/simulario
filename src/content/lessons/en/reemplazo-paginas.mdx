<Stage stage="theory">

A process uses its pages in some order: the **reference string**. Memory has a fixed number of **frames**. If the page is already in a frame, it is a **hit**; otherwise, a **page fault**. If no frame is free, the algorithm picks a **victim** that leaves memory.

| Algorithm | Who it evicts |
| --- | --- |
| **FIFO** | The page that was **loaded** first. Hits do not change the order. |
| **LRU** (least recently used) | The page whose last **use** is the oldest. Every hit refreshes it. |
| **OPT** (optimal, Belady's) | The page whose next use is **farthest in the future**, or that will never be used again. It needs to know the future. |
| **Clock** (second chance) | Frames form a circle and each has a **use bit**, set to 1 when the page is loaded or used. On a fault the hand looks at its frame: bit 1, clear it and move on; bit 0, evict that page, put the new one there with bit 1 and move one frame on. |

Free frames are filled in order, starting with frame 0. The first use of each page always faults.

</Stage>

<Stage stage="explain">

The right answer was **10 faults**: one more than with 3 frames.

**More frames are not always better.** This is **Belady's anomaly**. With 4 frames, FIFO keeps pages 1 to 4 until page 5 arrives at reference 7. From then on it evicts 1, 2, 3, 4 and 5 just before each one is needed again: references 7 to 12 all fault. The set of pages FIFO keeps with 4 frames does not always include the set it would keep with 3.

**FIFO does not look at use.** At reference 7 it evicts page 1, used two references earlier, because it was the first one loaded. The hits at references 5 and 6 did not move the queue.

**LRU and OPT do not suffer the anomaly.** They are **stack algorithms**: with *n* + 1 frames they always keep what they would keep with *n*, plus one more page. On this string LRU goes from 10 to 8 faults and OPT from 7 to 6 when going from 3 to 4 frames.

**What each one bets on.** FIFO ignores use. LRU assumes the recent past predicts the near future (locality). OPT reads the future, which can only be done after the fact: it is the yardstick, because no algorithm can fault less. On the *Classic* string with 3 frames: OPT 9, LRU 12, Clock 14, FIFO 15.

**Why Clock.** Exact LRU would have to record a time or move a list node on every memory access, billions per second. Instead, the hardware sets a use bit in the page-table entry, and Clock only reads and clears those bits when it needs a victim. If every bit is 1, Clock clears them all and behaves like FIFO: that is why it also shows the anomaly on this string.

**Faults no one can avoid.** The first reference to each page always faults. The Belady string has 5 different pages, so 5 faults is the minimum for any algorithm; with 5 frames or more, they all reach it.

**In real systems.** Linux approximates LRU with active and inactive page lists driven by the accessed bit, and since version 6.1 it includes the multi-generational LRU (MGLRU), enabled by default in distributions such as Fedora and Arch. Windows trims each process's working set. All of them approximate LRU; none is FIFO or OPT.

</Stage>
